# asd-ste100-writing — ASD-STE100 writing rule

**Purpose**
All responses and documentation use ASD-STE100 (Simplified Technical English). Use the exact technical term when no simple word is correct (for example: migration, RLS, Terraform, SHA, kill switch, webhook). Name each technical term the same way every time.

**Trigger**
You write a reply, report, ticket, or document for Tom or for a project.

**Do not use for**
- Choosing a document type or layout → `technical-writing`

## Core rules
- Use short sentences. Procedure steps: 20 words or fewer. Other sentences: 25 words or fewer.
- One idea in each sentence. One topic in each paragraph (6 sentences or fewer).
- Use the active voice. Use the imperative for steps ("Run the test.").
- Use simple verb tenses: present, past, future. Avoid the perfect and progressive tenses where you can.
- Use one word for one meaning. Do not change the word for the same thing.
- Use "must" for a rule. Use "can" for ability. Use "do not" for a ban. Do not use "should" or "may" to give an order.
- Use articles (the, a). Do not drop them.
- Do not use phrasal verbs with more than one meaning, idioms, jokes or figures of speech.
- Do not use gerund-led clauses to link steps. Write separate sentences.
- Put one action in each procedure step. Put warnings before the step they apply to.
- Write numbers as digits. Write dates as 2026-10-03 or "3 October 2026".
- Give the answer or the action first. Then give the reason.

## Check before you send
1. Is each sentence short and in the active voice?
2. Did you use one term for each thing?
3. Is each technical term necessary?
4. Can Tom read it once and know what to do?
